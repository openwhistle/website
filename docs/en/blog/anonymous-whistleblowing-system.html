How OpenWhistle protects whistleblowers' anonymity, and which installation mistakes put it at risk

What the software never stores about reporting people, where their IP address can still be visible, and how you prevent it as the operator.

27 October 2026 Updated 27 October 2026 6 min read OpenWhistle Contributors

An anonymous whistleblowing system is only as anonymous as its installation. OpenWhistle stores no IP address, no time of day and no metadata from attachments. What happens before the server, in the network and in a proxy in front, is the operator's part.

Transparency note

This article is written by the developers of OpenWhistle. Every statement about the software is backed by a file of release 2.4.0. Not legal advice.

Where the IP address is visible

What OpenWhistle does

Protection How
IP address, nginxclears 61 headers, among them X-Forwarded-For and 38 location headers added by CDNs; no access log [1]
IP address, appremoves the same headers again and clears the peer address before any handler runs [2]
IP address, databaseno table has an IP column [3]
Access to the reportcase number and PIN, no account, no email address; the status session holds only the case id, for 2 hours [4]
Timeof the report, messages and files only the date, never the time of day
AttachmentsGPS data, author and device are removed before anything is stored [5]
Contentencrypted, with a key of its own per report [6]
Third partiesno font, script or logo from another server; outbound connections are off until you switch them on [2]
Warningif an IP header still arrives, the dashboard, the report page and the status page warn [7]

The details are in the documentation: anonymity layers, timestamps and outbound requests.

Installation mistakes that break anonymity

Mistake Consequence How to avoid it
A reverse proxy in front writes an access logThe IP address and time of every report are in the log [8]turn the log off for this domain; the yellow warning shows that a proxy passes the address on
A CDN such as Cloudflare in frontThe provider sees every address and passes it on in the CF-Connecting-IP header [9]decide deliberately; offer an onion address as well
The app's or the onion listener's port is reachable past nginxThe headers are not cleared; requests can pose as Tor visitorsopen only ports 80 and 443; 8080 stays bound to 127.0.0.1 (onion trust boundary)
The report page only on the intranet or via the company VPNThe company's firewall and proxy see who reported and whenmake it publicly reachable and point employees to a private device outside the company network
Attachments in S3The bucket records each file's upload time to the second [10]use local storage, or restrict access to the bucket tightly
A database backup together with ENCRYPTION_KEYWhoever holds the backup reads every reportkeep the key apart from the backup
No valid certificateThe browser warns; employees give up or get used to warningsa certificate from Let's Encrypt (Install)

Tor: the strongest option

With an onion address, OpenWhistle is reachable only over Tor [11]. The reporting person's network then sees only a connection into the Tor network, and the server sees no address. How to set it up is in Offering an onion address.

What the law requires

In Germany, the identity of the reporting person must be kept confidential (§ 8 HinSchG) [12]. The reporting office “should” handle anonymous reports; the law does not require an anonymous channel (§ 16 Abs. 1). OpenWhistle offers both: anonymous, and confidential with a name.
